Chapitre 05
Dataview : interroger ses propres notes

Objectifs du chapitre

  • Écrire les quatre formes de requête : LIST, TABLE, TASK, CALENDAR.
  • Sélectionner une source avec FROM, filtrer avec WHERE, trier et grouper.
  • Utiliser les champs implicites que Dataview expose sur chaque note, sans que tu les aies écrits.
  • Reconnaître le piège de GROUP BY, qui produit un tableau vide sans le moindre message d'erreur.
  • Comprendre pourquoi ce plugin est ce qui rend une arborescence plate viable.

1. L'idée

Dataview lit le front-matter de toutes les notes du vault et t'en donne une vue de base de données. Tu écris une requête dans un bloc de code, et Obsidian affiche le résultat, recalculé à chaque ouverture de la note.

C'est le pendant du chapitre 3 : le front-matter est le contrat, Dataview est le moteur qui l'exploite. Sans lui, un vault plat n'est qu'un tas de fichiers ; avec lui, le classement se reconstruit à la demande, sous autant d'angles que tu veux.

```dataview
TABLE status, repo, updated
FROM "30-projets"
WHERE type = "project" AND status = "active"
SORT updated DESC
```

Le renversement à saisir : tu ne ranges plus, tu décris. Une note bien décrite apparaît toute seule dans toutes les vues qui la concernent — et dans celles que tu inventeras dans six mois, sans avoir à la déplacer.

2. Les quatre formes de requête

FormeProduitQuand
LISTUne liste de liens« Quelles notes… ? »
TABLEUn tableau, une colonne par expression « Quelles notes, et avec quelles valeurs ? »
TASKLes cases à cocher, cochables depuis la vue « Que reste-t-il à faire ? »
CALENDARUn calendrier pointé par une date Rare ; joli, peu actionnable
 
LIST
FROM "20-notes"
WHERE type = "concept"
SORT file.name ASC

TABLE WITHOUT ID file.link AS Note, updated AS "Dernière touche"
FROM "20-notes"
LIMIT 10

TASK
FROM "30-projets"
WHERE !completed

WITHOUT ID supprime la première colonne, ajoutée d'office, qui contient le lien vers la note. À utiliser dès que tu veux maîtriser tes colonnes, comme ci-dessus où le lien est remis à la main sous un nom choisi.

3. Choisir la source

FROM restreint l'ensemble de départ. Sans lui, la requête porte sur tout le vault.

FROM "30-projets"                -- un dossier (guillemets obligatoires)
FROM #safety                      -- une étiquette
FROM [[profinet]]                 -- les notes qui pointent VERS cette note
FROM outgoing([[profinet]])       -- les notes QUE cette note cite
FROM "20-notes" AND #safety       -- combinaisons avec AND / OR / -
FROM "20-notes" AND -#à-trier

FROM [[une note]] mérite d'être connu : c'est la version interrogeable des liens retour. Placé dans une fiche projet, il liste toutes les notes quotidiennes qui l'ont citée — un journal de projet reconstitué sans qu'on l'ait jamais tenu.

4. Les champs implicites

Au-delà de ton front-matter, Dataview expose sur chaque note un objet file que tu n'as rien eu à remplir :

ChampContenu
file.nameNom sans extension
file.linkLien cliquable vers la note
file.folderDossier parent
file.ctime / file.mtimeCréation et modification, vues par le système de fichiers
file.tagsÉtiquettes, corps et front-matter confondus
file.inlinks / file.outlinksLiens entrants et sortants
file.tasksLes cases à cocher de la note

file.ctime et file.mtime viennent du système de fichiers, pas de toi. Un git clone, une copie, une synchronisation les réécrivent toutes à la date de l'opération. C'est exactement pourquoi le schéma du chapitre 3 porte ses propres created et updated : eux voyagent avec le contenu.

Les champs en ligne

Dataview lit aussi des champs posés dans le corps de la note, avec un double deux-points :

Mesure effectuée le terrain. duree:: 45min
- [ ] Reprendre l'essai [échéance:: 2026-09-01]

Pratique pour annoter une ligne précise. À utiliser avec parcimonie : ces champs échappent au front-matter, donc au contrat du chapitre 3, donc au validateur.

5. Filtrer, trier, limiter

WHERE type = "project" AND status != "closed"
WHERE contains(tags, "safety")
WHERE created >= date(2026-01-01)
WHERE length(file.inlinks) = 0
WHERE contains(projects, this.file.link)

SORT updated DESC, file.name ASC
LIMIT 20

this désigne la note qui contient la requête. C'est ce qui permet d'écrire une requête générique dans un template : la même ligne, recopiée dans chaque fiche projet, donne à chaque fois le bon résultat.

Les fonctions les plus utiles : contains(liste, valeur), length(liste), date(…) et dur(…), choice(test, si_vrai, si_faux), filter(), map(), sum(), round().

6. Grouper — et le piège

GROUP BY regroupe les résultats par la valeur d'une expression. Et il change ce qui est visible à partir de là, ce que la documentation ne crie pas assez fort.

TABLE repo, updated
FROM "30-projets"
WHERE type = "project"
GROUP BY status

Cette requête s'affiche sans erreur, avec les bons groupes… et deux colonnes intégralement vides.

Après GROUP BY, une ligne de résultat n'est plus une note : c'est un groupe. Deux choses seulement existent à ce niveau — la clé du groupe (key) et rows, le tableau des notes qui le composent. repo et updated n'y sont pas définis, donc s'affichent vides.

Il faut passer par rows :

TABLE rows.file.link AS Projet, rows.repo, rows.updated
FROM "30-projets"
WHERE type = "project"
GROUP BY status

Ce défaut est passé au travers d'une revue dans le vault de la partie II : la requête s'affichait, les groupes étaient corrects, et personne ne remarquait les colonnes vides. Aucun test ne peut l'attraper — seule la lecture du résultat le révèle.

FLATTEN fait l'inverse : il déplie une liste pour produire une ligne par élément. Utile pour éclater les étiquettes ou les liens d'une note.

TABLE file.link
FROM "10-journal"
FLATTEN projects AS project
WHERE project = this.file.link

7. Les trois vues du vault de référence

Dans le vault de la partie II, les vues sont des notes ordinaires rangées dans 90-meta/vues/. Elles sont donc versionnées, liables, et modifiables sans toucher à la configuration.

Tableau de bord

TABLE status, repo, updated
FROM "30-projets"
WHERE type = "project" AND status = "active"
SORT updated DESC

Complété par la liste de l'inbox à trier et, via le plugin Tasks, les tâches en retard.

Concepts orphelins

LIST
FROM "20-notes"
WHERE type = "concept"
  AND length(file.inlinks) = 0
  AND (!see_also OR length(see_also) = 0)
SORT file.name ASC

C'est le détecteur de base de connaissance qui pourrit : une fiche que rien ne cite et qui ne cite rien ne sera jamais relue. La double condition couvre les deux formes d'absence — champ inexistant, et champ présent mais vide.

8. Dataview JS, et quand s'arrêter

Dataview offre aussi un mode JavaScript, dataviewjs, où tu construis le rendu à la main. Il permet tout, y compris des choses qu'on regrette.

Trois raisons de rester sur le langage de requête tant que possible : le JavaScript s'exécute à chaque affichage et peut ralentir sérieusement une note ; il est illisible pour qui reprend le vault ; et il permet d'écrire dans le vault, donc de casser des choses depuis ce qui devrait n'être qu'un affichage.

Si une vue demande vraiment du JavaScript, demande-toi d'abord si le schéma de front-matter n'est pas en cause. Les neuf fois sur dix, la requête complexe compense une donnée mal structurée.

Récapitulatif

  • Quatre formes : LIST, TABLE, TASK, CALENDAR. WITHOUT ID pour maîtriser les colonnes.
  • FROM accepte dossier, étiquette, lien entrant, outgoing(), et leurs combinaisons.
  • L'objet file expose des champs que tu n'as pas écrits — mais file.ctime ment après un clone.
  • this désigne la note porteuse : c'est ce qui rend une requête générique dans un template.
  • Après GROUP BY, seuls key et rows existent. Tout le reste s'affiche vide, sans erreur.
  • Une requête compliquée est presque toujours le symptôme d'un front-matter mal conçu.

Exercices

Exercice 1 — Écrire la requête

Écris une requête qui liste, sous forme de tableau, les fiches de 20-notes touchées depuis le 1er juillet 2026, avec leur date de mise à jour et leur nombre de liens entrants, les plus citées d'abord.

Voir la solution 
TABLE WITHOUT ID file.link AS Fiche,
      updated AS "Mise à jour",
      length(file.inlinks) AS Citations
FROM "20-notes"
WHERE type = "concept" AND updated >= date(2026-07-01)
SORT length(file.inlinks) DESC

Points d'attention : date(2026-07-01) sans guillemets — c'est un littéral de date, pas une chaîne ; length(file.inlinks) se répète dans la colonne et dans le tri, Dataview ne permet pas de trier sur l'alias ; et WITHOUT ID évite la colonne de lien en double.

Exercice 2 — Réparer la requête

Cette requête affiche les bons groupes mais des colonnes vides. Corrige-la, et explique en une phrase pourquoi elle ne produisait aucune erreur.

TABLE title, created
FROM "20-notes"
GROUP BY type
Voir la solution 
TABLE rows.file.link AS Note, rows.title, rows.created
FROM "20-notes"
GROUP BY type

Pourquoi pas d'erreur : après GROUP BY, title et created ne sont pas des noms invalides, ce sont des champs simplement absents du contexte de groupe. Dataview traite un champ absent comme vide — comportement voulu, qui évite qu'une note sans le champ fasse planter toute la vue. Le coût, c'est qu'une faute de frappe ou une erreur de portée passe inaperçue.

Le réflexe à prendre : une colonne vide sur toutes les lignes n'est pas un vault mal rempli, c'est une requête fausse.

Exercice 3 — Concevoir la vue manquante

Tu veux repérer les notes quotidiennes qui mentionnent un projet dont le status est closed — signe que tu travailles encore sur quelque chose que tu crois terminé. Comment t'y prends-tu ?

Voir la solution

La difficulté est que la condition porte sur une propriété de la note liée, pas de la note courante. Il faut déplier les liens puis suivre le lien :

TABLE WITHOUT ID file.link AS Jour, project AS Projet
FROM "10-journal"
FLATTEN projects AS project
WHERE project AND project.status = "closed"
SORT file.name DESC

FLATTEN produit une ligne par projet cité, puis project.status déréférence le lien pour lire le front-matter de la cible.

Le WHERE project AND … n'est pas décoratif : une note quotidienne sans projects produit un project nul, et déréférencer nul remonterait une erreur.

Autre approche, plus simple à lire mais moins directe : partir des projets clos et lister leurs liens entrants avec FROM [[…]]. Il faudrait alors une requête par projet — d'où l'intérêt de la version ci-dessus, qui tient en une vue.
